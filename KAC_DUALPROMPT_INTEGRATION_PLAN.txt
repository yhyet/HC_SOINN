KAC分类器集成到DualPrompt方法工作计划书
==================================================

项目目标
--------
将KAC分类器集成到LAMDA-PILOT_2项目的dualprompt方法中，参考codaprompt的集成方式，实现可训练的KAC分类器替换原有的线性分类器。

参考实现分析
------------
1. Codaprompt集成方式回顾：
   - 在CodaPromptVitNet中添加use_kac参数和kac_config配置
   - 在__init__中根据use_kac选择KACLayer或nn.Linear
   - 实现update_fc和generate_fc方法支持增量学习
   - 在models/coda_prompt.py中添加参数解析、优化器配置、评估方法

2. DualPrompt结构分析：
   - 使用PromptVitNet类（utils/inc_net.py）
   - PromptVitNet使用backbone（通过timm创建）
   - 分类器在backbone内部：backbone/vit_dualprompt.py中的VisionTransformer类
   - 分类器是self.head = nn.Linear(self.embed_dim, num_classes)
   - forward中通过res['logits'] = self.head(x)输出logits

------------

- 确保KACLayer的输出维度是num_classes

关键技术点
----------
1. 分类器位置：dualprompt的分类器在backbone内部（self.head），而不是在PromptVitNet中
2. 参数传递：需要将use_kac和kac_config从args传递到backbone的VisionTransformer
3. 接口兼容：确保KACLayer的输出格式与nn.Linear兼容（都是logits）
4. 增量学习：检查dualprompt是否需要支持增量学习的类别扩展

实施顺序建议
------------
1. 阶段一 → 修改backbone（核心集成）
2. 阶段二 → 检查PromptVitNet（如果需要）
3. 阶段三 → 修改训练流程（功能实现）
4. 阶段四 → 修改评估流程（验证功能）

与Codaprompt集成的差异
----------------------
1. 分类器位置不同：
   - Codaprompt: 在CodaPromptVitNet中（self.fc）
   - DualPrompt: 在backbone内部（self.head）

2. 网络结构不同：
   - Codaprompt: 使用CodaPromptVitNet，有独立的fc层
   - DualPrompt: 使用PromptVitNet，分类器在backbone内部

3. 参数传递路径：
   - Codaprompt: args → CodaPromptVitNet.__init__ → 直接创建fc
   - DualPrompt: args → PromptVitNet.__init__ → get_backbone → timm.create_model → VisionTransformer.__init__

4. 需要特别注意：
   - DualPrompt通过timm.create_model创建backbone，需要确保KAC参数能正确传递
   - 可能需要修改get_backbone函数或timm模型创建过程

风险评估
--------
1. timm模型创建：timm.create_model可能不支持自定义参数，需要检查如何传递KAC参数
2. 参数传递链：需要确保KAC参数从args正确传递到VisionTransformer
3. 接口兼容性：确保KAC分类器与现有代码完全兼容
